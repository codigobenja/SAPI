Informe de Aporte Técnico: Evolución del Motor de Inteligencia Artificial
Proyecto: Análisis de Sentimiento - Hackathon 2025 Responsable: equipo data science

1. Resumen Ejecutivo
Nuestro aporte se centró en liderar la evolución técnica del modelo de lenguaje, transformando un script de entrenamiento estático en un sistema de Aprendizaje Continuo y Dinámico. Este proceso garantizó que la IA no solo clasifique textos, sino que sea capaz de adaptarse al feedback humano y escalar mediante una arquitectura de producción profesional.

2. Fases del Desarrollo y Desafíos Superados
Fase 1: Cimentación (Entrenamiento_modelo_binario_mejorado)

Desafío: Obtención y depuración de la base de datos inicial. El reto fue limpiar datos crudos para que la IA pudiera entender matices entre servicios positivos y negativos.

Solución: Se implementó el vectorizador TF-IDF para transformar palabras en pesos numéricos. Se establecieron las métricas base (Accuracy y F1-Score) para medir el éxito inicial.

Resultado: Un modelo funcional que servía como prueba de concepto pero que era estático (había que programar todo de nuevo para actualizarlo).

Fase 2: Del Modelo Estático al Dinámico (Modelo_con_autoaprendizaje_binario)

Desafío: La "deriva de datos". Los modelos de IA pierden precisión si el lenguaje de los usuarios cambia y no tienen feedback.

Solución: Creamos un sistema de Validación Humana. Implementé una interfaz en Gradio que permitía a un auditor corregir a la IA en tiempo real. Estas correcciones se guardaban automáticamente en el archivo .csv, permitiendo que el modelo "aprendiera" del error sin tocar el código fuente.

Resultado: Pasamos de un modelo "muerto" a uno Dinámico que evoluciona con el uso, integrando una capa de auditoría de calidad de datos.

Fase 3: Industrialización y Automatización (Beta_modelo_final)

Desafío: La complejidad técnica de unificar el preprocesamiento y el modelo para que el equipo de Backend pudiera utilizarlo sin errores.

Solución: Introdujimos el concepto de Pipeline Unificado de Scikit-Learn. Esta estructura encapsula todo el proceso (traducción de texto + lógica de decisión) en un solo objeto.

Resultado: Se generaron los "robots" finales (.pkl). Gracias a este Pipeline, el equipo de desarrollo puede cargar el modelo como una sola unidad, eliminando la necesidad de manejar el CSV o los diccionarios de palabras por separado en el servidor.

3. Métodos Técnicos Utilizados
TF-IDF (Term Frequency-Inverse Document Frequency): Método para que la IA priorice palabras clave ignorando conectores irrelevantes.

Regresión Logística con Probabilidad: No solo clasificamos, sino que obtenemos el nivel de confianza (ej. "Negativo con 85% de certeza"), permitiendo filtrar dudas.

Serialización Joblib/Pickle: Técnica para "congelar" la inteligencia y entregarla al equipo de Backend lista para producción.

Unificación de Datasets: Fusión de bases de conocimiento propias y de colaboradores para aumentar la robustez.

4. Por qué llegamos a estas soluciones
Llegamos a este punto porque una Hackathon no se gana solo con precisión, sino con escalabilidad. El paso al Pipeline fue la solución técnica para que nuestra IA fuera integrable en cualquier App. El paso al Autoaprendizaje fue la solución estratégica para asegurar que nuestra herramienta sea útil a largo plazo para un auditor, permitiendo que la máquina y el humano trabajen en equipo.
